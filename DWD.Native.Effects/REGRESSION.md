本节只针对 `DWD.Native.Optimized`，下方保留的是复制来的原版历史记录。

- 从空 build 独立生成并构建 Release，无旧项目中间目录警告。最后一次 CTest 三组全过：
  后台存储/内存/扫描/帧节奏/缩放缓存、宿主几何、使用时长历史与双模式。
- 真实预览集成：44 个 MP4 全部加载就绪并返回像素尺寸，覆盖竖屏、1906×1080、1080p、4K。
  快速切换、停止立即重开、加载取消、无效文件错误后恢复、循环重开、限时析构全部通过。
  本机此次各视频 ready 约 156–313ms；这是媒体测试，不是 UI 点击到显示首帧的严格基准，
  也没有据此声称比原版快多少。
- 使用电脑操作技能实际操作副本：启动/切换封面；4K 已有代理应用；重复应用；刷新保留
  共享视频；普通预览与共享预览往返；搜索 P29/清除；翻页；进入/完成取景；叉号隐藏和恢复。
- 4K 代理运行时，主屏 2560×1440、副屏 1920×1080 的 HWND 几何正确，两个屏幕露出区域
  都有非黑动态采样。暂停后两屏变化点为 0；恢复后两屏重新变化。
- 带取景框隐藏到托盘后，没有残留可见控制窗口；两屏均保持动态。超过共享资源保留时间后
  再次运行 EXE，恢复同一个控制器并重建共享预览。
- 4K 代理切到 1080p 原片：新播放器首帧就绪后旧播放器正常退出，稳定后只有控制器和
  当前播放器。副屏动态采样通过；此时主屏被其他窗口覆盖，不当作主屏像素再次通过。
- 点击恢复静态壁纸：两个动态输出窗口均消失，两块屏幕露出区域非黑且静止。
- 通过开发用 `--exit` 正常退出控制器，日志记录资源释放/壁纸恢复，没有强杀正常控制器。

## 修复后通过

- Release 构建；build/publish SHA256 一致。
- CTest：桌面宿主几何与使用时长历史/双模式，两组通过。
- 原生媒体测试：初次打开、暂停继续、UpdateVideo、12 次快速切换、4 次停止后立即重开、加载中取消再开、缺失文件报错与错误后恢复、循环重启、析构限时。
- 全库加载：当前目录 44 个 MP4 全部发出 ready，返回真实像素尺寸，包含 544×720、1906×1080、1920×1080、3840×2160；不是只判断宽高比非零。该项验证媒体事件与尺寸，不等同于逐个视频完整观看或帧率测量。
- 真实 UI：普通预览与共享预览往返两轮；4K/1080p 应用与更换；设置五个分页打开/收起；搜索 P29、翻页、刷新保留预览；取景进入/完成、带框收回托盘无残留；打开/关闭使用时长窗口；叉号收回托盘并再次运行 EXE 恢复同一进程。
- 桌面：两个 WorkerW 子输出分别为 2560×1440 和 1920×1080，几何正确。副屏 63 个露出采样点动态且非黑；暂停后 0 点变化，继续后 63 点变化；恢复静态后输出为 0，画面静止且非黑。
- 正常销毁：开发 --exit 发出退出事件，控制进程退出；日志记录媒体释放与恢复壁纸。未强制杀正常控制器。
- 最终 EXE 再测：普通预览、叉号隐藏、重新打开、应用 P29、共享动态预览、双屏几何与副屏动态采样通过。最终进程运行 publish 版本。

## 不能声称已覆盖

- 最初报告的永久卡死没有稳定现场复现；已修复静态检查发现的阻塞/渲染混用风险并增加日志，不声称唯一根因完全证实。
- 主屏被其他用户应用覆盖，未验证主屏真实桌面像素动态；只验证输出窗口尺寸与挂载结构。
- 自动化工具未提供任务栏托盘区域，未实际鼠标点击托盘“退出”。验证了叉号隐藏和与托盘退出相同的销毁流程，二者不能混称。
- 没有真实睡眠/锁屏、热插拔、Explorer 重启、驱动故障注入、长时间稳定性、其他电脑/Windows 版本测试。
- 未对缓存清理执行真实删除，也未移动用户视频/缓存目录；没有为回归覆盖这些破坏性操作。
- 共享 D3D 初始化/释放仍在 UI；预览超时保证 UI 能结束载入状态，不保证失去响应的底层驱动能自行恢复。
